# Приклад: «Поворот світла» — puzzle без сервера

Навчальний приклад, не готове ТЗ для запуску. Усі тести planned, всі gates pending. ID локальні для цього прикладу.

## PRODUCT

Коротка спокійна puzzle для дорослих: повертати плитки й провести промінь до цілі. Перша платформа — Android; один портретний режим, українська мова. Гіпотеза OBJ-001: 4 з 5 нових гравців без усної підказки завершать навчальний рівень і самі почнуть другий. Перевірка на прототипі, результат поки невідомий. Якщо ні — змінити підказку/керування до виробництва контенту.

## REQUIREMENTS

MVP: 3 авторські рівні, поворот, візуальний шлях променя, перемога, перезапуск, локальне відкриття рівнів. Немає таймера, поразки, ліміту ходів, валюти, реклами, процедурної генерації чи акаунтів. Якщо часу не вистачає — скоротити декор; не прибирати перевірку розв’язності.

REQ-001 — поворот і промінь; Must, OBJ-001.
- AC-001: tap рухомої плитки обертає її на 90° за годинниковою стрілкою й перераховує шлях; tap нерухомої не змінює стан.
- AC-002: шлях завершується на межі, непрозорій плитці або повторі пари (координати, напрямок входу); нескінченний цикл неможливий.

REQ-002 — перемога та повтор; Must, OBJ-001.
- AC-003: потрапляння променя в ціль переводить playing у won лише один раз і відкриває наступний рівень, якщо він існує. На останньому показано «Усі рівні пройдено» без переходу за межі списку.
- AC-004: retry повертає початкові орієнтації, стан playing і скидає прапорець перемоги поточної спроби; вже відкриті рівні не закриваються.

NFR-001 — збереження прогресу; Must, OBJ-001.
- AC-005: після успішного збереження перемоги й перезапуску відкриті рівні доступні offline; незавершена спроба починається заново.
- AC-006: помилка запису не скасовує перемогу в поточній сесії; показано «Прогрес не збережено» з повтором запису, не заявлено успішне збереження.

## DESIGN та GAME

UX-001: меню рівнів → поле → перемога → наступний/меню. Pause перекриває поле, ігнорує tap; resume повертає той самий стан у процесі. Після завершення процесу незавершений рівень скидається. Error завантаження контенту — повідомлення й повернення в меню; на порожньому каталозі старт недоступний. Звук опційний, не потрібний для розв’язання. Плитки відрізняються формою, а не лише кольором.

Core loop: обрати рівень → повертати → бачити промінь → запалити ціль → наступна задача. Поле 4×4; координати x,y = 0…3, напрямки N/E/S/W. Одне джерело, одна ціль; без розгалуження променя. Типи: порожня (пропускає), блок (зупиняє), дзеркало / або \ (відбиває), джерело, ціль. Дзеркала мають 4 орієнтації, де 0/180 і 90/270 еквівалентні. Випадковості немає.

Для /: E→N, N→E, W→S, S→W. Для \: E→S, S→E, W→N, N→W. Тут напрямок означає напрямок руху променя. Ціль поглинає промінь із будь-якого боку. Шлях містить стани (координати, напрямок); максимум 64 унікальні стани поля. Це логічна межа алгоритму, не вимір швидкодії.

Формат рівня: id, schemaVersion=1, grid[4][4], sourceDirection, initialRotations, movableCells, knownSolution. Перший навчальний fixture: джерело (0,1) E, рухоме дзеркало \ у (1,1), ціль (1,0), решта порожня. Один поворот міняє дзеркало на / і приводить до цілі. Для двох інших рівнів контент ще треба створити й перевірити (Q-001).

ADR-001 — proposed: чиста логіка променя окремо від рендерингу; передача UI списку сегментів і ознаки won. Альтернатива — фізичні колізії рушія, але для дискретної сітки вони ускладнюють відтворення. Стек обирається після перевірки досвіду автора (Q-002). Жодного backend: лише максимальний індекс відкритого рівня, version=1; повторний запис того самого прогресу ідемпотентний. Немає персональних даних/SDK/платежів.
